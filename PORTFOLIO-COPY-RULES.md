# Portfolio Copy Rules

Read this before editing any public page in `codesbyshrey.github.io`. Keep copy short, concrete, and recruiter-readable. Do not write meta-copy about page structure.

## 1. Voice in one line

Public-facing, recruiter-readable, concrete-noun first. Sentences short. No descriptions of the page itself.

## 2. Pattern for any card or paragraph

Every card or short paragraph should answer, in this order:

```txt
Role / artifact
What I did
Tools or methods
Why it matters
```

- Paragraphs: 1-2 sentences max.
- Cards: one strong sentence plus chips or bullets for tools/methods.
- Skip "why it matters" if the project name and tools already make it obvious.

## 3. Prefer concrete nouns

Lean on these instead of abstractions:

- React, TypeScript, Python
- AWS, Postgres
- LLM evaluation, RAG, ASR
- clinical roleplay, OSCE, NBME-style scenarios
- usability testing, mixed-methods research, trust calibration
- EMT, biomechanics coaching, NASM, swim instruction
- physical therapy clinic exposure
- Glenoid implant patent, shoulder arthroplasty
- haptics, accelerometer, fall detection

## 4. Banned phrases

Do not use these on any public page. They read as internal vault language.

- proof surfaces
- system context
- portfolio paths
- stacked chapters
- product-shaped
- where X becomes public
- this page is organized as
- source bank
- language layer

## 5. Frameworks (use sparingly)

Use at most one per page, only when it earns the line.

- `Problem -> Person -> Process -> Product`
- `Perception -> Intention -> Expression`
- `Learning is Unobstructed Self Expression`

## 6. Hard nos

- No `PhD`, `Ph.D`, or `phd` objective copy.
- Do not call Shreyas a physical therapist, PT, or DPT candidate.
- For PT-clinic exposure, use only: `Physical Therapy Clinic Work`, `Physical Therapy Clinic Exposure`, or `clinic-based movement education`.
- No SymbiGrid / PI-symbi grid references on public pages.
- No "build something special" / "passion for excellence" filler.

## 7. Weak -> stronger examples

Use these as calibration when rewriting copy.

Weak:
> A page organized as stacked chapters of human factors and biomedical context.

Stronger:
> MS Human Factors at Bentley. BS Biomedical Engineering at RPI. Cloud and full-stack practice through AWS and Coding Dojo.

Weak:
> Proof surfaces tied to these ideas live in PI Bonita.

Stronger:
> PI Bonita: AI wellness MVP. React, Gemini, structured TIME / SPACE / SELF triage with explicit safety boundaries.

Weak:
> Where evaluation becomes public.

Stronger:
> Mixed-methods evaluation of clinical AI: trust calibration, evidence use, and safety-sensitive failure modes.

Weak:
> Patient-facing context shaped a humane communication style.

Stronger:
> EMT and Physical Therapy Clinic Exposure. Patient transport, handoffs, and clinic-based movement education across diverse populations.

Weak:
> This page is organized as a reverse-chronological map across clinical, digital, embodied, and physical systems.

Stronger:
> Reverse-chronological work, color-coded by system: clinical AI, full-stack builds, embodied interfaces, and clinic / movement context.

Weak:
> A holistic framework for cognitive systems and embodied design.

Stronger:
> Practice Intuition: design think tank for human factors, biomechanics, and AI wellness coaching.

## 8. Quick checklist before commit

- [ ] No banned phrase from section 4.
- [ ] No `PhD` / `physical therapist` claims.
- [ ] No SymbiGrid links or mentions.
- [ ] Every card answers role / what / tools / why (or earns the cut).
- [ ] No paragraph longer than two sentences.
- [ ] At most one framework reference per page.
